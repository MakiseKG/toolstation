JavaScript 是现代网页最重的资源之一，脚本体积直接影响首屏速度。好消息是，开发时为了可读性写的**注释、空格、换行**，发布前全都可以安全去掉——这就是 JavaScript 压缩（Minify）。

这篇文章讲清楚[JS 压缩工具](/tools/js-minifier)的原理和正确用法。

## 压缩做了什么

看一段未压缩的 JS：

```js
// 计算总和
function sum(a, b) {
  // 返回两数之和
  return a + b;
}
```

压缩后：

```js
function sum(a,b){return a+b}
```

注释、换行、多余空格全部移除，**逻辑一字未动**。体积从 45 字节降到 30 字节。

## 压缩的收益

- **下载更快**：脚本体积减小，首屏解析更快
- **省流量**：CDN 和用户流量都减少，移动端收益更明显
- **提升评分**：Lighthouse / PageSpeed 的脚本体积指标直接受益

```text
原始 120 KB → 压缩后 ≈ 80 KB（省 33%）
```

配合 gzip/Brotli 压缩，实际传输体积还会再小一半以上。

## 压缩后能还原吗

可以。**纯压缩**只去掉空白和注释，用格式化工具就能还原成可读结构——变量名、函数名、逻辑顺序全部保留。

但注意区分：

| | 压缩（Minify） | 混淆（Uglify/Obfuscate） |
|---|---|---|
| 去掉空白注释 | ✅ | ✅ |
| 重命名变量/函数 | ❌ | ✅ |
| 能否还原 | 格式化即还原 | 几乎不可还原 |
| 适用场景 | 减体积 | 防破解 |

[JS 压缩工具](/tools/js-minifier)只做压缩不混淆，**不破坏你的代码可维护性**。

## 什么时候压缩

- ✅ **发布上线前**：构建产物必压缩，这是前端标准动作
- ✅ **内联脚本**：页面里的 `<script>` 内联代码也可以先压缩
- ❌ **开发调试时**：压缩后报错堆栈难定位，开发阶段保留源码

## 总结

- **JS 压缩 = 移除注释/空格/换行**，逻辑不变、体积减 20-40%
- 纯压缩可格式化还原；混淆才无法还原，本工具只做压缩
- 发布前压缩、开发时保留源码，是性能与可维护性的平衡
- 用[JS 压缩工具](/tools/js-minifier)一键完成，代码全程本地处理，不会外传
