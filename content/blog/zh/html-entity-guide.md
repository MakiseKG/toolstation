你在网页上看到 `<` 符号，源代码里可能写的是 `&lt;`——这就是 HTML 实体（HTML Entity）。它负责告诉浏览器「把这段文字当普通字符显示，而不是当成标签解析」。理解 HTML 实体，是**防止 XSS 攻击**的基础功。这篇文章讲清实体原理，并用 [HTML 实体编解码工具](/tools/html-entity) 演示编码与解码。

## 为什么需要 HTML 实体

浏览器会把 `<b>` 解析成加粗标签。如果你想让用户看到字面的 `<b>`，就必须转义：

```html
<!-- 浏览器显示：<b> 是加粗标签 -->
&lt;b&gt; 是加粗标签
```

## 常见实体对照表

| 字符 | 实体写法 | 说明 |
|------|----------|------|
| `<` | `&lt;` | 小于号 |
| `>` | `&gt;` | 大于号 |
| `&` | `&amp;` | 与符号（最容易被漏掉） |
| `"` | `&quot;` | 双引号 |
| `'` | `&#39;` | 单引号 |
| `©` | `&copy;` | 版权符号 |

**注意 `&` 本身也要转义**——`&amp;` 是「实体中的实体」，漏掉它会导致后续实体解析错乱。

## XSS 攻击与实体编码

XSS（跨站脚本攻击）最常见的成因是：**把用户输入直接插进 HTML，没做转义**。攻击者提交 `<script>alert(1)</script>`，如果直接输出，这段脚本就会在你的页面上执行。

```js
// 危险：直接拼接用户输入
innerHTML = userInput;

// 安全：先做 HTML 实体编码
innerHTML = escapeHtml(userInput);
```

凡是用户可控的内容（昵称、评论、URL 参数），输出到 HTML 前**必须编码**。这是前后端都要守住的底线。

## 总结

- HTML 实体让浏览器把字符当字面量显示，不当作标签解析
- `&`、`<`、`>`、`"`、`'` 是最常用的五个转义字符
- **输出用户输入前必须编码**，这是 XSS 防护的关键一步
