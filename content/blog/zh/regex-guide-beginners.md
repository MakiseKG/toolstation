正则表达式（Regular Expression，简称 regex）是开发者必须掌握的技能之一。它用一套「模式匹配」的语法，在文本中查找、提取或替换符合规则的字符串。本文从零开始，带你建立正则的完整知识框架。

## 正则是什么？

简单说，正则就是**描述字符模式的模板**。例如：

```javascript
/^\d{11}$/   // 匹配恰好 11 位数字（中国大陆手机号）
/\b[A-Z]{3}\b/  // 匹配 3 个大写字母组成的单词
```

处理日志、数据清洗、表单校验、代码搜索……正则无处不在。

## 基础语法：字符与元字符

### 字面字符

大部分字符匹配它们本身：`cat` 匹配字符串中的 "cat"。

### 元字符（特殊含义的字符）

| 元字符 | 含义 | 示例 |
|---|---|---|
| `.` | 任意单个字符（除换行） | `c.t` 匹配 cat、cot |
| `\d` | 任意数字（0-9） | `\d{4}` 匹配 4 位数字 |
| `\w` | 字母、数字、下划线 | `\w+` 匹配单词 |
| `\s` | 空白字符（空格、制表符、换行） | |
| `^` | 字符串开头 | `^Hello` |
| `$` | 字符串结尾 | `world$` |
| `\b` | 单词边界 | `\bcat\b` 只匹配独立单词 cat |

### 量词：控制出现次数

| 量词 | 含义 |
|---|---|
| `*` | 0 次或多次 |
| `+` | 1 次或多次 |
| `?` | 0 次或 1 次 |
| `{n}` | 恰好 n 次 |
| `{n,}` | 至少 n 次 |
| `{n,m}` | n 到 m 次 |

### 字符类与分组

```regex
[abc]      // a、b、c 中的任意一个
[a-z]      // 任意小写字母
[0-9]      // 任意数字，等价于 \d
[^abc]     // 除 a、b、c 之外的字符
(ab|c)     // 分组 + 或运算
```

## Flags（标志）：改变匹配行为

| Flag | 含义 | 说明 |
|---|---|---|
| `g` | 全局匹配 | 匹配所有结果，而不是第一个就停 |
| `i` | 忽略大小写 | `/hello/i` 匹配 Hello、HELLO |
| `m` | 多行模式 | `^` 和 `$` 作用于每一行 |
| `s` | 让 `.` 匹配换行符 | 默认 `.` 不匹配换行 |
| `u` | Unicode 模式 | 正确处理中文等非 ASCII 字符 |

用 [正则测试工具](/tools/regex-tester) 时，Flags 可以直接勾选。

## 实战：常用正则库

以下是开发中最高频的几组模式，[正则表达式测试工具](/tools/regex-tester) 内置了这些模板，一键套用：

| 用途 | 模式 |
|---|---|
| 邮箱 | `^[\w.+-]+@[\w-]+\.[\w.-]+$` |
| 手机号（中国大陆） | `^1[3-9]\d{9}$` |
| URL | `^https?://[\w.-]+(:\d+)?(/[\w./?%&=-]*)?$` |
| IPv4 地址 | `^(\d{1,3}\.){3}\d{1,3}$` |
| 正整数 | `^\d+$` |
| 十六进制颜色 | `^#?([0-9a-fA-F]{3}\|[0-9a-fA-F]{6})$` |
| 身份证号 | `^\d{17}[\dXx]$` |

## 高效调试的三个技巧

1. **分段验证**：长正则拆成小块分别测试，确认每块行为正确再组合
2. **善用测试文本**：准备包含边界情况的样例（空行、首尾空格、大小写混合）
3. **从简单开始**：先用 `\d+` 确认基础匹配，再逐步叠加限制条件

## 常见误区

- ❌ `[abc]+` 表示「ab、bc 的组合」——实际是「a、b、c 中任意字符重复」
- ❌ 忘记转义 `\` 在字符串中的写法（如 JS 中要写 `\\d`）
- ❌ 不加 `g` 标志，只匹配到第一个结果

## 总结

- 正则用模式模板匹配文本：元字符 + 量词 + 字符类 + 分组
- Flags 控制匹配范围：`g` 全局、`i` 忽略大小写、`m` 多行
- 高频模式（邮箱、手机号、URL）建议直接复用现成模板
