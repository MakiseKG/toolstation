Unix 时间戳（Unix Timestamp，也叫 Epoch Time）是计算机系统中最通用的时间表示方式，但它也是前后端联调时最容易出错的环节：有人用秒，有人用毫秒，两边时间就对不上了。这篇文章帮你彻底搞懂时间戳的原理和转换方法，并推荐一款 [时间戳转换工具](/tools/timestamp) 提高日常效率。

## 什么是 Unix 时间戳

Unix 时间戳是从 **1970 年 1 月 1 日 00:00:00 UTC**（Unix 纪元）开始，到指定时刻经过的秒数或毫秒数：

- `1754092800` 是**秒级**时间戳
- `1754092800000` 是**毫秒级**时间戳

它本身不携带时区信息，因此是跨系统交换时间的标准格式——无论在世界哪个角落，同一个时刻的时间戳都相同。

## 秒与毫秒：最容易踩的坑

不同语言默认返回的时间戳精度不同：

```js
// JavaScript 默认毫秒
Date.now();                        // 1754092800000
Math.floor(Date.now() / 1000);     // 1754092800（秒）

// PHP 默认秒
time();                            // 1754092800
```

前后端混用秒和毫秒，时间会相差 **1000 倍**（约 3 年）。**拿到时间戳先确认单位，再做处理。**

## 常见应用场景

- **接口签名与过期校验**：JWT 的 `exp` 字段、验证码过期时间都基于时间戳
- **数据库存储**：`bigint` 类型比字符串日期更省空间，且天然可排序
- **缓存与日志**：缓存过期时间、日志时间戳统一用时间戳便于比较

## 时间戳与日期互转

```js
// 时间戳 → 日期
new Date(1754092800000).toISOString();  // "2025-08-01T16:00:00.000Z"

// 日期 → 时间戳
new Date("2025-08-01").getTime();       // 1754092800000
```

## 总结

- 时间戳从 1970-01-01 UTC 起算，无时区概念
