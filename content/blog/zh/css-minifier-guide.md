CSS 文件越大，浏览器解析样式表越慢，首屏渲染越容易被拖后。而绝大多数 CSS 里都藏着大量**空格、换行、注释**这类「排版垃圾」——它们只服务于人类可读性，对浏览器毫无意义。压缩（Minify）就是把这些去掉，让文件变小。

这篇文章讲清[CSS 压缩工具](/tools/css-minifier)的原理和使用。

## 压缩到底去掉了什么

看一段「还没压缩」的 CSS：

```css
/* 清除默认间距 */
body {
  margin: 0;
  padding: 0;

  /* 字体 */
  font-family: "Helvetica", sans-serif;
}
```

压缩后会变成：

```css
body{margin:0;padding:0;font-family:"Helvetica",sans-serif}
```

对比一下：注释没了、空格没了、换行没了、最后的分号也省了。**功能完全等价，体积却小了一大截。**

## 能省多少体积

- 没压缩的 CSS 里，注释和空白通常占 **20%-40%**
- 压缩后文件可以减小 **20%-40%**，具体取决于你写注释和换行的习惯

```text
原始 50 KB → 压缩后 ≈ 32 KB（省 36%）
```

对大型项目的样式文件，这个节省直接换算成更快的下载和解析。

## 压缩 vs 混淆，别混淆

| | 压缩（Minify） | 混淆（Obfuscate） |
|---|---|---|
| 去掉空白注释 | ✅ | ✅ |
| 重命名类名变量 | ❌ | ✅ |
| 代码可读性 | 仍可读 | 几乎不可读 |
| 主要目的 | 减小体积 | 防止逆向 |

[CSS 压缩工具](/tools/css-minifier)只做压缩，**不重命名任何东西**——你的类名、变量名原样保留，随时可以格式化成可读版本。

## 压缩与格式化的配合

工作流通常是：

1. 开发时写可读的、带注释的 CSS
2. 构建发布前**压缩**成单行版本
3. 出问题时再**格式化**回去排查

这三步对应[压缩工具](/tools/css-minifier)的输出，配合使用既保住开发体验，又保住线上性能。

## 总结

- **CSS 压缩 = 去掉空白/注释/冗余分号**，功能不变、体积减 20-40%
- 压缩 ≠ 混淆，本工具不重命名你的类名，随时可还原
- 开发写可读版、发布前压缩，是前端性能优化的基本动作
- 用[CSS 压缩工具](/tools/css-minifier)一键完成，代码全部在本地处理

页面变快的第一步，往往就是给样式表减重。
