从模板文件、邮件 HTML 或旧项目里复制出来的代码，往往是一整行几千字符、毫无缩进的「压缩包」。排错时根本找不到标签在哪里。**HTML 格式化是每个前端都需要的「复原术」**。这篇文章介绍格式化与压缩的用法和场景，并推荐一款 [HTML 格式化工具](/tools/html-formatter)。

## 为什么需要格式化 HTML

格式化的核心是把嵌套结构还原成可读的层级：

```html
<!-- 格式化前 -->
<div><p>你好</p><span>世界</span></div>

<!-- 格式化后 -->
<div>
  <p>你好</p>
  <span>世界</span>
</div>
```

好处很直接：

- **嵌套层级一目了然**，快速定位漏掉的闭合标签
- **多人协作可读**，代码评审、交接不再痛苦
- **对比 diff 更清晰**，格式化后做版本对比，改动一眼可见

## 格式化 vs 压缩

| | 格式化 | 压缩 |
|---|---|---|
| 缩进换行 | 有 | 无 |
| 文件体积 | 变大 | 小约 20-30% |
| 适用场景 | 阅读、调试、维护 | 生产上线、邮件模板、页面性能 |

压缩会把 HTML 变成单行，常用于：

- **减小页面体积**：首屏加载更快
- **邮件 HTML**：很多邮件客户端对体积和行数有硬限制
- **模板注入**：把 HTML 塞进 `<script type="text/template">` 时体积更小

## 总结

- 格式化还原嵌套结构，压缩减小体积，两者互补
- 阅读调试用格式化，生产上线用压缩
